# CoworkingFinder — ИИ-консультант

Учебный проект: ИИ-консультант, который за короткий разговор собирает бриф на рабочее место и подбирает коворкинг. Слева — диалог из четырёх вопросов, справа — живая подборка, которая сужается после каждого ответа. В конце — объяснение выбора и демонстрационная бронь. На вопросы по документам («Где есть бесплатная парковка?») отвечает RAG: свой BM25-поиск по корпусу из 30 документов + LLM со ссылками на источники.

## Для кого
Студенты, фрилансеры, удалённые сотрудники и небольшие команды, которым нужно подобрать рабочее место.

## Основной сценарий
1. Пользователь открывает сайт: помощник здоровается и спрашивает город, справа — весь каталог (10 из 10).
2. Отвечает на 4 вопроса брифа (город → бюджет → что важно → сколько человек) кнопками или одной фразой: «Москва до 800 ₽ с переговорной».
3. После каждого ответа подборка пересортировывается: подходящие места сверху, остальные гаснут, счётчик уменьшается.
4. Помощник подводит итог: лучшее совпадение, почему оно подходит, источник `cw-…`; можно снять условие или сравнить варианты.
5. Пользователь открывает место, выбирает дату и получает **демонстрационный** билет.

Подробнее — в [`spec/product/scenarios.md`](spec/product/scenarios.md).

## Как запустить
Откройте `frontend/index.html` двойным щелчком в браузере. Сервер, интернет и установка зависимостей не требуются.

Для разработки можно поднять локальный сервер (удобно для DevTools):

```bash
python -m http.server 5173 --directory frontend
```

### С поиском по документам (RAG)
```bash
pip install -r backend/requirements.txt
export LLM_API_KEY=sk-...            # без ключа работает офлайн-заглушка вместо LLM
uvicorn backend.app:app --port 8000
```
Откройте http://localhost:8000/ и задайте вопрос, например «Как отменить бронь и вернут ли деньги?». Ответ придёт со ссылками `D01…D30`; если в документах ответа нет — «В документах нет этой информации.» Другие LLM (Ollama, OpenRouter) и API — в [`backend/README.md`](backend/README.md).

Без браузера: `python -m backend.ask "Где есть бесплатная парковка?"`

## Benchmark
```bash
python benchmark/run.py --compare    # сравнение версий поиска
python benchmark/run.py              # 15 вопросов → Recall@k, MRR, Accuracy, Correct Rejection Rate
```
Корпус, вопросы, эталоны, результаты и разбор ошибок — [`benchmark/README.md`](benchmark/README.md).

## Тесты
```bash
node tests/assistant.test.js                 # движок брифа
python -m unittest discover -s tests         # BM25 (в т. ч. пример из методички) и RAG-пайплайн
```
Интерфейс проверяется вручную по [`tests/README.md`](tests/README.md).

## Что готово (КТ1)
- Документация SDD в `spec/`.
- Сайт ИИ-консультанта в `frontend/`: разговор-бриф с прогрессом, живая подборка с метками условий, сравнение, карточка места с демо-бронью, светлая/тёмная тема, адаптив.
- Локальный движок разбора запросов `frontend/assistant.js` и демонстрационные данные `frontend/data.js`.
- Автотесты движка в `tests/`.

## Что готово (КТ3)
- RAG: корпус `corpus/` (30 документов D01–D30), свой BM25-индекс, вызов LLM, отказ при отсутствии сведений, FastAPI `POST /api/ask`.
- Интерфейс отправляет вопросы (фразы с «?», начинающиеся с «как», «где», «сколько», «можно ли»…) и непонятые фразы в RAG и показывает ответ с источниками.
- Benchmark: 10 вопросов + 5 ловушек, метрики и разбор ошибок.

## Ограничения
- Бриф и подборка по-прежнему разбираются **правилами** (ключевые слова и регулярные выражения); BM25 + LLM отвечают на вопросы по документам.
- Без `LLM_API_KEY` вместо нейросети работает офлайн-заглушка (цитаты из найденных документов); качество ответов у неё ниже.
- Бронирование имитируется в браузере, **не сохраняется** и никуда не отправляется.
- Текущий бриф хранится только в `localStorage` браузера.
- Все названия, адреса, цены и характеристики коворкингов вымышленные.

## Структура
```
frontend/    сайт: index.html, styles.css, data.js, assistant.js, app.js
backend/     FastAPI + RAG: rag/ (text, bm25, corpus, llm, pipeline), app.py, ask.py
corpus/      30 документов D01–D30 для поиска (вымышленные данные)
benchmark/   вопросы с эталонами, run.py, results/
spec/        product/ — продукт и сценарии; tech/ — архитектура и RAG
tests/       автотесты движка, BM25 и RAG; чек-лист ручной проверки
```
